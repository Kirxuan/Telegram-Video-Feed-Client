# Stage 25 后续设备验收清单

日期：2026-09-09。此文件是后续验收协议，不是当前执行授权。本次用户禁止任何实体机操作；以下实体机项目全部为 **尚未验证**。仅 API 36 AOSP x86_64 模拟器上的 Compose、Room 和受控 Media3/EGL 测试已有执行记录。

本次收尾已刷新：常规 Compose 101/101；小屏大字、横屏、平板各 40/40。全屏入口验证完整视口边界、48dp 实测触摸目标、触摸进入/退出及元数据恢复。运行目标固定为 `emulator-5580 / CVF_STAGE25_API36_X86_64`；这些结果不提供 iQOO 12 或 ARM64 硬件性能证据。

## 1. 候选与比较条件

正式版本仍为 Stage 24 / 1.1.0。Stage 25 生产默认启用 C1 双播放器；C2 与 SampleQueue 仍是互斥独立候选。四个播放候选必须由同一源码、同一构建环境生成；R8 和数据库加密不混入播放比较。

| 候选 | SampleQueue | 双池 | 备用输出 |
|---|---|---|---|
| Baseline | 关闭 | 关闭 | 无 |
| SampleQueue | 开启 | 关闭 | 无备用播放器 |
| PoolC1 | 关闭 | 两个实际 ExoPlayer | 无持久备用 Surface |
| PoolC2 | 关闭 | 两个实际 ExoPlayer | 消费离屏帧的 EGL Surface；保护内容退至 C1 |

Owner Promotion 四组均关闭。生产默认 HLS、安全解析/MP4 回退、混合 ABR、缓冲参数、画质偏好必须相同。原画偏好不得被强制降级来改善成绩。每次报告记录 APK SHA-256、依赖版本、目标设备/系统、内容键/表示版本的脱敏映射、分辨率、编码、时长与大小；不得包含账号、会话或真实凭证。

受控网络采用同一 trace、seed 和限速/延迟/丢包模型。冷缓存、部分缓存和热缓存分别比较，不能跨组混算。网络模拟结果单独列示；真实 Telegram 吞吐、设备温度和功耗不能由模拟推断。测试素材只使用得到授权的普通流式视频，不导出受保护内容。

## 2. 采样和指标

1. 30 次只用于初筛。正式 P95 至少预先约定每组 200 次自然前向稳定切换，并完成至少三轮交错 AB/BA；保留每轮分布和置信区间，不只合并挑选好的轮次。
2. 固定启动/切换超时，在跑之前确定。保存每次尝试的成功、失败、超时、主动跳过和取消。不能删除失败或把失败当零延迟。报告成功回调的 P50/P90/P95/P99 时，标题必须写明条件分布，并同时报告总尝试数、失败率、超时率；若无法确定包含未完成样本的全量 P95，写“不可判定”或对应超时下界。
3. 分开报告自然前向全部切换与 READY 备用准备命中子组。C2 离屏首帧绝不作为用户可见首帧。当前诊断以绑定/手势事件到当前可见 Surface 的渲染回调为代理，还需在设备上以帧时间线与允许内容的视觉复核确认正确帧已呈现。
4. 初始缓冲、seek 等待、用户暂停和播放中的重缓冲分开计量。重缓冲次数、播放时间占比、每次平均时长、P95/P99、未恢复次数同时报告；不只看有恢复事件的平均数。
5. seek 在同样的绝对位置、缓存条件和拖动轨迹下比较，从最终用户目标提交到目标帧可见计时，包含错误/超时。检查旧请求取消、缓存区间复用和最终目标正确性。
6. 未缓存请求预算、TDLib 观察到的下载字节增量、磁盘缓存字节和实际网络流量分别记录；请求长度不能替代网络流量。下载计数无法归因时保留 unknown，不伪造精确值。

`scripts/run-swipe-first-frame-benchmark.ps1` 会保留失败/超时并写出 `.log.attempts.json`；最多 1000 次。原始日志、尝试账本和 READY 命中分布应一起保存。脚本不能单独证明物理显示、能耗或正式发布条件。

## 3. 启用门槛（所有真实设备结果尚未验证）

| 检查 | 门槛 |
|---|---|
| 自然前向首帧 P95 | 相对改善至少 15%，且绝对改善至少 75ms；不得通过失败样本减少获得 |
| READY 准备命中 | 首帧目标 150ms 内，作为独立子组，不能替代全部切换 |
| 卡顿和重缓冲 | 卡顿率、平均重缓冲时长不得恶化，长尾与未恢复事件一并复核 |
| 当前视频 seek | 不得明显回退；应预先约定统计容差并报告分布 |
| PSS | 增量不超过基线 25% 与 64MiB 中较小者；基线和候选同阶段测量 |
| Codec/图形 | 跟踪真实 Codec 实例、图形缓冲、Surface、native 分配，不能只看 Java heap |
| 能耗 | 同条件持续浏览增量目标不超过 10%；电源/温度/时长一致 |
| 正确性 | 零双音频、错帧、账号串用、缓存误删、Codec 泄漏、第三播放器 |
| 后台 | 无无意义预热；STANDBY、EGL 线程和请求及时释放 |

任一安全/资源门槛失败则停用候选并复测单播放器回退。缺少真实测量或正式统计证据时，生产开关继续关闭。

## 4. 状态与故障矩阵

- 慢速自然前向、快滑越过多个页面、突然反向、轮次边界反向；最终稳定目标成功显示，无即时重复和错帧。反向不得增加第三播放器。
- 当前视频/唯一下一条被删除、内容更新、权限变化、频道筛选和随机队列重排；旧代次/账号/质量准备不得交接。
- 原画、720p、省流、自动；HLS 有效/无效 manifest、读取失败、解码失败，单次 MP4 回退；保持 supportsStreaming=false 拦截。
- 完整缓存的短片、长片尾段、部分缓存下降、真实下载不足、重缓冲、拖动 seek；只有安全状态允许下一准备。
- 计费网络默认关闭预加载；Wi-Fi/移动网络切换、断网/恢复、FLOOD_WAIT、低存储、内存压力、热限制、省电。
- 暂停/恢复、后台/前台、旋转、Activity 重建、退出播放、退出账号、清缓存及进程释放；确认所有权和旧更新隔离。
- 保护内容切入/切出：窗口安全状态先于对应画面，离开前保留旧绑定保护；不允许截图/导出保护内容用于验收。
- 注入第二 Codec 申请失败、备用准备错误、EGL 初始化失败；分别验证单播放器或 C1 回退和资源释放。

## 5. 独立工程与安全验收

- **R8/资源压缩**：单独 APK 比较已可构建；后续需 ARM64 TDLib JNI、Hilt、Room、账号恢复、播放与退出 smoke。体积减少不等于运行时正确。
- **Baseline Profile**：当前仅覆盖无需账号的凭证入口。授权后的频道、筛选、播放路径仍未覆盖；不使用持久真实账号注入 CI，不以 Fake 生产入口替代真实路径。
- **16KiB native**：`verify-native-pages.py` 独立检查 ELF PT_LOAD 对齐/同余与 APK 条目偏移，另由 zipalign 交叉验证。仍需 16KiB 页 ARM64 环境真实加载和播放验证，不能由普通 ARM64 或 x86_64 UI 测试代替。
- **TDLib 数据库加密候选**：只为新空库生成随机密钥并以 Keystore AES-GCM 封装至 noBackupFilesDir。旧非空库无密钥文件返回 MigrationRequired；密文/Keystore 不可读返回 Unavailable，禁止空密钥回退和自动覆盖旧库。旧库两阶段迁移未实现，必须独立设计和验收。Room 元数据数据库尚未加密。
- **Android 8/9**：本次已移除 SQLite 3.24 UPSERT 语法；API 26/28 的实际系统 SQLite 与安装运行仍需独立兼容验证。
- **主机门禁已恢复**：历史 Robolectric Android 16 依赖加载为外部环境阻塞；本次以原配置正常重跑完整 `test` 已通过，没有复制受限缓存、删除测试、放宽验证或替换 Android 版本。主机通过仍不替代实体机 install+launch、Keystore 或真实账号路径。
