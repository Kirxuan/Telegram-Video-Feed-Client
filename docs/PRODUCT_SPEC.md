## 1. 产品定义

VELORA（曜流）是一个供个人使用的原生 Android 应用，品牌标语为“曜流，让精彩自然流动”（“VELORA — Let Content Flow.”）。每位使用者通过自己的 Telegram API 参数和个人账号授权，选择已经加入且仍有权访问的频道，将其中的普通视频消息建立本地元数据索引，然后以竖向短视频信息流连续播放。

应用不提供服务器、Web 后台、广告、统计、埋点、商业化、上传或社交互动功能。应用必须尊重 Telegram 权限和内容保护，不扩大账号本身的访问能力。

## 2. 成功标准

第一版成功必须同时满足：

1. 真实 TDLib 用户授权流程可在测试手机完成，不使用模拟成功。
2. 用户能从有权访问的频道中多选并持续建立普通视频元数据索引。
3. 中英文话题标签能按实体信息准确提取并以 OR/AND 筛选。
4. 竖向滑动时只有当前页面的一个共享播放器发声。
5. 支持流式播放的视频通过 TDLib 分段读取，不通过消息链接或伪 HTTP 地址播放。
6. 不支持流式的视频不会自动完整下载。
7. 视频字节不离开应用内部存储，媒体缓存默认不超过 500MB。
8. 没有真实验证的行为被清楚标记为“尚未验证”。
9. 用户可选择 Telegram 提供的较小服务端视频文件以降低网络压力，不通过本地转码伪装为省流。

## 3. 目标用户与使用前提

- 目标用户是愿意自行申请并保管 Telegram API 参数的个人使用者。
- 用户自行申请并保管 Telegram API ID/API Hash。
- 用户只使用一个 Telegram 账号；退出后可登录另一个账号，但不会并行保留多账号会话。
- 用户必须遵守频道规则、Telegram 条款和所在地法律。
- 应用只访问当前账号本来有权访问的内容。

## 4. 第一版范围

### 4.1 授权与会话

- FR-AUTH-01：release 首次启动时要求使用者填写自己的 API ID/API Hash；格式通过并完成 Android Keystore 加密保存后初始化 TDLib。debug 可在没有设备端配置时使用被 Git 忽略的本机开发值。
- FR-AUTH-01A：任何非 debug 构建不得注入构建者的本机 API 参数；公开 APK 反编译后不得出现维护者值。
- FR-AUTH-01B：格式错误、Keystore/密文不可用或 TDLib 拒绝参数时返回可恢复配置状态；修改参数会先关闭旧 TDLib Client，收到 Closed 后再用新参数创建唯一 Client。
- FR-AUTH-02：支持国家区号和手机号手动输入。
- FR-AUTH-03：支持 Telegram 验证码。
- FR-AUTH-04：支持两步验证密码。
- FR-AUTH-05：状态完全由 TDLib updateAuthorizationState 驱动。
- FR-AUTH-06：处理等待参数、等待手机号、等待验证码、等待密码、已授权、正在退出、已关闭和错误状态。
- FR-AUTH-07：TDLib 在应用私有目录保存会话并在下次启动恢复。
- FR-AUTH-08：支持明确退出账号；退出时停止同步、预加载和播放，并清除账号相关本地索引与缓存。
- FR-AUTH-09：错误转换为可理解的简体中文，FLOOD_WAIT 显示可重试时间。
- FR-AUTH-10：验证码和密码不持久化，流程结束后清除内存引用。

若 TDLib 固定版本新增等待邮箱、注册或其他授权状态，第一版必须安全显示“当前登录步骤暂不受支持，请更新应用”，不得误判为登录成功。是否扩展为可交互步骤需单独评审。

### 4.2 频道

- FR-CH-01：只显示当前账号已加载并有权访问的聊天。
- FR-CH-02：聊天类型必须为 chatTypeSupergroup，且对应 supergroup.isChannel=true。
- FR-CH-03：排除用户已离开、被封禁或无法访问的频道。
- FR-CH-04：显示频道名称并支持本地搜索。
- FR-CH-05：支持多选、显示选择数量并持久保存选择。
- FR-CH-06：频道失去权限时停止继续扫描，将其标记为不可用，并从最终队列排除。

### 4.3 消息索引与同步

- FR-SYNC-01：只收录 TDLib messageVideo，不收录 document、animation、videoNote、paidMedia、story 或直播。
- FR-SYNC-02：首轮先扫描近期有限页，每完成一页立即用 Room 事务保存。
- FR-SYNC-03：应用前台且资源策略允许时继续扫描更早历史。
- FR-SYNC-04：每个频道保存最旧已扫描消息游标和最新已同步位置。
- FR-SYNC-05：下次启动从游标继续，不从头重复全量扫描。
- FR-SYNC-06：处理 updateNewMessage、消息内容更新和消息删除。
- FR-SYNC-07：数据库唯一键为 chatId + messageId。
- FR-SYNC-08：删除消息标记 isDeleted=true，并从标签关联和播放队列排除。
- FR-SYNC-09：编辑说明文字后，在一个事务中更新说明文字与标签关联。
- FR-SYNC-10：扫描只读取元数据，不触发完整视频下载。
- FR-SYNC-11：自动重试有最大次数、指数退避和抖动，可取消且幂等。

首轮近期页数和每页大小不是产品常量；实现阶段必须集中配置并以设备/账号人工验收确定。无论配置值如何，都必须满足“每页落库”和“可继续游标”。

### 4.4 标签

- FR-TAG-01：优先读取 caption 的 formattedText.entities 中 textEntityTypeHashtag。
- FR-TAG-02：支持中文、英文、数字、Unicode 组合标记和下划线。
- FR-TAG-03：保留消息中原始显示文本，并另存标准化键。
- FR-TAG-04：标准化去掉前导 #，进行 Unicode NFKC 规范化，并用 Locale.ROOT 转小写。
- FR-TAG-05：同一视频内按标准化键去重。
- FR-TAG-06：仅当 TDLib 没有 hashtag 实体时，才使用经过单元测试的 Unicode 回退扫描器。
- FR-TAG-07：回退扫描器拒绝孤立 #、嵌入普通单词内部的 # 和不含有效标签字符的文本。
- FR-TAG-08：标签页显示每个标签在当前有效索引中的视频数量。

### 4.5 筛选语义

筛选表达式固定为：

    (频道 A OR 频道 B OR …) AND 标签条件

标签条件有两种模式：

- OR：视频至少包含一个选中标签。
- AND：视频必须包含全部选中标签。

空频道选择表示没有可播放视频；不会隐式选择全部频道。空标签选择表示不施加标签限制。更改频道、标签或标签模式后立即生成新队列，取消旧队列的播放和预加载请求。

### 4.6 播放顺序

- FR-ORDER-01：最新优先按 publishTime 降序，并用 chatId/messageId 作为稳定次序补充键。
- FR-ORDER-02：随机模式在一个会话轮次内不重复。
- FR-ORDER-03：一轮结束后重新洗牌；新一轮首条不得等于上一轮末条，除非队列只有一条。
- FR-ORDER-04：删除、失效或失去权限的视频立即从剩余队列移除。
- FR-ORDER-05：筛选条件变化后开始新会话轮次。
- FR-ORDER-06：播放历史只记录进度、完成状态和最近播放时间，不改变最新优先的发布时间定义。

### 4.7 竖向视频信息流

- FR-FEED-01：使用 Compose 竖向分页组件。
- FR-FEED-02：页面稳定后才把共享播放器绑定到最终当前项。
- FR-FEED-03：当前页面自动播放；其他页面立即停止并不得发声。
- FR-FEED-04：快速滑动时取消过期绑定，只保留最新稳定页面请求。
- FR-FEED-05：不在重组中创建播放器；不为每页创建播放器。
- FR-FEED-06：进入后台立即暂停；返回前台按用户设置决定是否恢复。
- FR-FEED-07：失去音频焦点时暂停或按系统语义降低音量；耳机断开时暂停。
- FR-FEED-08：支持暂停/继续、静音/恢复和按设置重播当前视频。
- FR-FEED-09：显示频道、说明文字、标签、发布时间、加载、错误、重试和空状态。
- FR-FEED-10：断网时保留已索引元数据浏览，不承诺播放未缓存媒体。

### 4.8 TDLib 分段读取

- FR-MEDIA-01：只播放 video.supportsStreaming=true 的普通视频。
- FR-MEDIA-02：自定义 TelegramMediaDataSource 消费 DataSpec.position 和 DataSpec.length。
- FR-MEDIA-03：TelegramFileManager 将请求转换为 TDLib downloadFile(fileId, priority, offset, limit, false)。
- FR-MEDIA-04：读取 TDLib 私有文件前等待 updateFile 证明所需连续区间可读。
- FR-MEDIA-05：支持文件中间读取、seek、未知长度、暂未准备、网络变化、文件清理和播放器释放。
- FR-MEDIA-06：DataSource 的阻塞读取只发生在 Media3 加载线程，禁止主线程等待。
- FR-MEDIA-07：close、快速滑动和超时释放所有权；无其他所有者时取消 TDLib 下载。
- FR-MEDIA-08：读取块大小集中配置，初始候选范围为 1MB–4MB，最终值由真机测量决定。
- FR-MEDIA-09：当前视频使用高优先级；下一条使用较低优先级。
- FR-MEDIA-10：提供自动选择、省流模式、720p 和原画四档偏好；只从 TDLib 提供的直接服务端视频文件中选择。
- FR-MEDIA-11：当前播放与下一条预加载必须使用同一质量策略和最终 fileId，不得先预加载原画再播放省流版本。
- FR-MEDIA-12：候选缺失、刷新失败/超时、信息无效或 codec 不安全时回退 direct MP4；Telegram HLS 只接受安全解析后的内部资源并在失败时单次回退，不做本地转码或第二播放内核。

video.supportsStreaming=false 时必须：

1. 不自动完整下载。
2. 不通过其他 URL 或协议规避。
3. 显示精确文案：“该视频暂不支持流式播放。”
4. 允许继续滑动。

### 4.9 原消息链接

- FR-LINK-01：只在 TDLib messageProperties 允许时调用 getMessageLink。
- FR-LINK-02：成功后使用 Android Intent 打开 HTTPS Telegram 消息链接。
- FR-LINK-03：无法生成或无法打开时显示“无法打开 Telegram 原消息”。
- FR-LINK-04：消息链接只用于导航，绝不作为媒体播放地址。

### 4.10 缓存

- FR-CACHE-01：TDLib 应用私有媒体文件是唯一媒体字节缓存来源，不启用 Media3 SimpleCache 完整副本。
- FR-CACHE-02：默认上限 500MB，可选 200MB、500MB、1GB、2GB、5GB、10GB、15GB、20GB。
- FR-CACHE-03：当前播放与下一条预加载由运行时所有权保护。
- FR-CACHE-04：其他视频按最近最少使用清理。
- FR-CACHE-05：启动时检查，达到上限主动清理，进入后台可轻量清理。
- FR-CACHE-06：不依赖应用退出回调。
- FR-CACHE-07：存储不足先停止预加载，再清理未保护缓存。
- FR-CACHE-08：一键清空时停止预加载、暂停并关闭当前 DataSource，再删除媒体缓存；保留登录、频道、标签和播放历史索引。
- FR-CACHE-09：缓存文件被系统或用户清理后，索引不得崩溃，播放可重新请求。

### 4.11 网络、电量与温度

| 条件 | 当前视频 | 下一条预加载 |
|---|---|---|
| Wi-Fi、正常温度、非省电、非低电量 | 允许 | 按用户 Wi-Fi 设置允许少量数据 |
| 移动数据 | 允许 | 默认关闭；用户可显式开启 |
| 无网络 | 仅已缓存区间可用 | 禁止 |
| 省电模式或低电量 | 允许 | 禁止 |
| 热状态 NONE/LIGHT | 允许 | 按网络与电量策略 |
| 热状态 MODERATE | 允许 | 停止或显著缩小；第一版选择停止 |
| 热状态 SEVERE 及以上 | 仅当前视频 | 禁止 |

网络变化使用 ConnectivityManager.NetworkCallback，不按秒轮询。热状态在 API 29+ 使用 PowerManager 热状态监听；API 26–28 没有该平台能力时标记为 UNKNOWN，并依赖网络、省电和低电量策略，不伪造温度值。

### 4.12 内容保护

- FR-PROTECT-01：message.canBeSaved=false 或消息属性表明受保护时，不显示保存、导出或本地分享能力。
- FR-PROTECT-02：受保护视频仍只通过当前账号、官方 TDLib 和内部私有缓存访问。
- FR-PROTECT-03：播放受保护内容期间启用 FLAG_SECURE；离开后恢复窗口策略。
- FR-PROTECT-04：禁止截图、录屏规避、替代账号获取、URL 重构或复制到公共目录。

## 5. 页面

### 5.1 启动页

显示 API 参数配置、TDLib 初始化和登录状态恢复。缺少凭证时显示 API ID/API Hash 输入和申请说明，不显示伪登录；API Hash 使用密码遮罩，提交后从 UI 状态清除。

### 5.2 登录页

按授权状态显示手机号、验证码或两步验证密码输入；包含加载、中文错误和退出/重试行为。输入内容不持久化。

### 5.3 频道选择页

显示频道名称、搜索、多选、已选择数量、保存按钮和每个频道的扫描状态。

### 5.4 标签筛选页

显示标签、视频数量、多选、OR/AND 切换和清空筛选。

### 5.5 信息流页

全屏竖向视频，显示元数据、播放状态、错误/重试、原消息跳转、暂停和静音。无视频、断网、不支持流式和受保护状态必须明确。

### 5.6 设置页

包含自动/省流/720p/原画质量偏好、缓存上限/占用/清空、Wi-Fi 和移动数据预加载、播放顺序、重播设置、退出账号、应用版本、TDLib 版本和默认关闭的调试信息开关。

启动器名称、登录页品牌名、品牌标语与创造者署名跟随 Android locale：中文语言显示“曜流”、中文标语及“创造者：麒轩”，英文及未单独支持的语言回退 `VELORA`、英文标语及 `Created by Kirxuan`。其余 1.0 功能 UI 继续使用简体中文；支持深色模式、常见竖屏手机和系统返回手势，不复制任何短视频品牌元素。

## 6. 权限

第一版只申请：

- android.permission.INTERNET
- android.permission.ACCESS_NETWORK_STATE

明确禁止联系人、短信、通话记录、手机状态、麦克风、摄像头、精确/后台位置、通知和广泛存储权限。手机号由用户手动输入。

## 7. 数据保存与删除

- 当前授权实现将 TDLib database root 放在 app-private `noBackupFilesDir`，files root 放在 app-private `cacheDir`；未来会话与媒体实现也必须保持在应用内部存储。
- Room 保存频道、视频、标签、标签关联、游标和播放历史元数据。
- DataStore 保存非敏感偏好；不得保存验证码、密码、API Hash、TDLib 数据库密钥或会话对象。API Hash 只能以 Android Keystore AES-GCM 密文保存到 noBackupFilesDir 专用文件。
- 退出账号清除账号相关 Room 数据、TDLib 数据库/会话和媒体缓存，但保留不敏感的应用级设置。
- 清空媒体缓存不删除登录状态、频道索引、标签索引或播放历史。
- 卸载应用由 Android 删除应用私有数据。

## 8. 错误与重试

必须有显式中文状态：登录失败、验证码错误、密码错误、网络断开、TDLib 初始化/数据库失败、权限丢失、消息删除、文件失效、不支持流式、编码不支持、播放超时、缓存/存储不足、Room 异常、FLOOD_WAIT、快速滑动取消、后台暂停、解码失败和消息链接失败。

自动重试统一要求：最大次数有限、指数退避、遵守 FLOOD_WAIT、支持取消、不阻塞主线程、使用幂等数据库事务。授权凭证错误不自动重复提交；用户需更正输入。

## 9. 明确不支持

- Telegram Bot API、机器人账号、手写 MTProto、Telethon、Pyrogram。
- 多账号并行、服务器、Web 后台。
- 视频上传、点赞、评论、转发。
- Stories、直播、视频通话、视频留言。
- 普通文档视频、付费媒体。
- 保存、导出、相册写入或内容保护绕过。
- React Native、Flutter、Expo。
- 广告、统计、埋点、第三方分析 SDK。
- Google Play 或其他商店发布、商业发布签名。

## 10. 质量门槛

- 核心策略有单元测试和 Fake 基础设施。
- UI 状态有 Compose/仪器测试。
- 每阶段运行适用的 test、lint、assembleDebug。
- TDLib native、真实授权、真实频道扫描、区间 seek、编码和温度行为必须使用真机人工验收。
- debug 继续用于开发验证；公开 release APK 必须经过免维护者凭证扫描、独立长期签名和 ARM64 真机门槛。
